## Methodology

- Load generator: [k6](https://k6.io), 50 virtual users for 30s, one full CRUD cycle (list → create → get → update → delete) per iteration.
- Both services run in Docker via their own `docker-compose.yml`, each **capped to exactly 1 CPU core** (`cpus: "1.0"`); Postgres runs unconstrained in both, so it's never the bottleneck.
- The two services are benchmarked sequentially, never concurrently, so each gets the CI runner to itself.
- Both apps expose an identical schema and identical endpoints — see [`axum-item-crud/README.md`](axum-item-crud/README.md) and [`bun-item-crud/README.md`](bun-item-crud/README.md) for details.
- Numbers below come from a single CI run and will vary between runs — GitHub-hosted runners are shared, general-purpose VMs, not dedicated benchmarking hardware. Treat this as a directional comparison, not a lab-grade result.
